> 要点概览
> 
> 智能体进入陌生环境，通常要么靠人标注数据再训练，要么干脆破罐子破摔。RSIAgent 走了第三条路： **不训练任何参数，让智能体自己在环境里反复试错，把学到的东西沉淀成可复用记忆** 。课程 agent 决定探索什么、执行 agent 操作环境、验证 agent 只看反馈判断成败，再配合 **先广后深** 两阶段探索。OSWorld 2.0 上，partial score **71.97 → 78.98** 、binary accuracy **37.80 → 42.68** ；Agents' Last Exam 上 **83.75 → 84.82** 、 **49.25 → 50.75** ， **反超 GPT-6 Astra** 6.38 和 2.56 个百分点——底座只是开源的 GLM-5.3 加 Kimi-K3。

## 1\. 问题：智能体换个环境就失灵

数字智能体这条路线已经很成熟了：观察界面信息，执行点击或者写代码，在真实软件里完成用户任务。但论文指出了一个现实问题—— **真实环境是不断变的** 。

智能体被部署到一个新环境时，它的接口约定、工具行为、使用惯例、失败模式，很可能压根没被预训练知识覆盖到。已有做法主要分两支：

**一是补数据再训练。** 收集这个环境里的交互数据，继续训练模型。有效，但成本高，而且在私有环境或持续变化的环境里根本没法用——你拿不到数据，也无法对每个环境都训一次。

**二是免训练的上下文管理。** 通过组织上下文里的记忆信息来提升表现，这条线近两年有明确进展。

论文认为光有这两条还不够。 **光记住成功的轨迹是不够的** ——真正的适应能力应该包含发现因果关系：什么动作、在什么条件下、会导致什么结果。再把这些关系组织成可复用的结构。

> 论文的类比
> 
> 人学新软件也是递归的：先搞清楚该学什么，再动手试、收集经验，最后从结果里提炼有用的知识。关键在于这不只是经验累积，而是 **因果发现** ——主动试不同动作并观察后果，逐渐推断出哪些因素决定了成功、失败和状态转移。

于是问题变成了： **智能体能不能自主地从新环境里发现因果关系、写成可复用记忆、拿它改进自己？**

论文的总览图分两块：左边是课程、执行、验证三个角色首尾相接的递归闭环，记忆随之从 演化到 ；右边是基准成绩，RSIAgent 在 OSWorld 2.0 和 Agents' Last Exam 两张表上都是最高分。

## 2\. 框架：三个 agent 加一份会进化的记忆

RSIAgent 的骨架是一个 **多智能体 harness** ，三个角色构成一个递归循环。设计得很有意思的地方在于： **记忆的更新权不在执行 agent 手里，而在验证 agent 手里。**

### 2.1 执行 agent：唯一持有可进化记忆的角色

执行 agent 是系统的主策略模型，负责理解环境、生成可执行动作。它配备一份 **持久记忆** ，存三类东西：环境专属知识、可复用的流程与脚本、历次执行学到的教训。

这份记忆是 **可进化的** ：验证 agent 评估完结果后，执行 agent 把有依据的经验固化下来——补充新知识，必要时修订或删除过时信息。更新后的记忆被后续的执行 agent 实例继承，于是有用知识在整个探索过程中不断累积。

> 记忆为什么能进化
> 
> 记忆之所以能持续变强，关键就在这个 **演化环节** 。执行 agent 不是简单地把每次交互记录下来，而是经过验证 agent 的评估之后，把有依据的经验固化进记忆——补充新知识、修订或删除过时信息。更新后的记忆被后续执行 agent 实例继承，有用知识就在整个探索过程中不断累积。

### 2.2 验证 agent：只看环境反馈，不看执行过程

验证 agent 是独立评估器，负责判断执行 agent 是否真正满足了任务要求。为了让判断可靠，它 **只查环境反馈** ——执行结果、界面状态这些可观测证据，判断完全建立在这些信号上。

关键设计是： **验证 agent 与执行 agent 的私有推理和记忆相互隔离** ，论文说这有助于减少评估时的 **相关性错误** 。道理不复杂——如果评估方能看到执行方的思考过程，就容易被执行方的叙述带偏；隔离之后，验证判断只能落在可观测证据上。

它返回一个成功或失败的判定加上支撑证据，这个判定再决定 **对应的经验是否应该被固化进记忆** 。

### 2.3 课程 agent：决定下一步探索什么

课程 agent 是高层协调者，负责决定系统接下来该探索什么。具体做法是根据当前目标、累积记忆和过往探索结果，为执行和验证两个 agent 生成合适的练习任务。

它通过选择 **前置技能、有信息量的变体、失败驱动的练习、压力测试用例** 来确定探索方向，逐步扩大可进化记忆的覆盖范围。论文给了一个停止条件： **当生成的任务不太可能再贡献实质性新知识时，探索就结束。**

## 3\. 方法：先广后深两阶段递归探索

在多智能体框架之上，RSIAgent 把自主探索组织成两个互补的阶段。理解这两阶段的分工，是读懂这篇论文的关键。

下面用一个 FreeCAD 支架复刻任务走一遍完整流程：广度阶段从空环境并行铺开支架、槽、沉头法兰、口袋、腔体五组任务，各自积累经验后汇入广度经验记忆库；深度阶段改为串行，先定位销轴失败，再对齐孔位通过并沉淀一条经验，最后加支撑筋再次通过。两阶段的产物一起进入逐步精炼的记忆，测试时直接复用。

图 2 · RSIAgent 整体流程，以一个 FreeCAD 任务为例

### 3.1 广度递归自探索（BRS）：先把环境摸清楚

BRS 的目标是快速建立对新环境的 **广谱理解** ，靠收集多样的交互经验达成。它遵循一个递归探索循环：

课程 agent 先生成探索任务 → 执行 agent 执行 → 验证 agent 评估结果。

为了保证覆盖的广度， **每一轮课程 agent 都提出多个跨不同探索方向的任务，并行执行和验证** 。收集到轨迹和验证反馈后，课程 agent 用累积经验识别剩余的知识缺口，为下一轮生成更有信息量的任务。

通过这个递归过程，BRS 逐步扩大对环境专属知识、可复用流程和失败模式的覆盖。

实现上，BRS 的名义预算是 **八个探索项目，最多四个并发执行** 。预算在 **波次之间** 检查，不打断正在进行的波次。

### 3.2 深度递归自探索（DRS）：再攻坚难题和边界

DRS 的目标是通过聚焦重要知识缺口、困难案例和边界条件来 **精炼** 累积记忆。它是一个 **串行的递归循环，难度递增** 。

课程 agent 先提出一个 **容易暴露不可预测问题、隐藏约束或记忆弱点** 的挑战任务。执行 agent 用累积记忆尝试，验证 agent 评估并给出有依据的反馈。基于得到成功、失败和新暴露的不确定性，课程 agent 为下一轮生成 **更难** 的后续任务。

有一个设计细节值得注意： **每一条被验证过的经验，在下一个任务被提出之前就已经固化进记忆了** 。这让 DRS 能持续把 agent 推向更难、更少被探索过的案例。

DRS 没有固定预算，一直串行推进直到课程 agent 判断不再需要更多练习。同样值得注意的是： **在这个阶段，一次成功的练习不会自动终止探索** ——课程 agent 要审视验证结果和累积记忆，再决定是否值得继续。

### 3.3 测试时记忆复用

探索结束后，累积的记忆被 **冻结** ，交给执行 agent 用于测试。此阶段课程 agent 和所有记忆更新 **全部停用** 。

给定目标任务，执行 agent 直接复用记忆里存着的流程、发现的约束和失败教训来指导动作，验证 agent 则对照任务要求评估结果。这个「动作—验证」循环持续到验证 agent 确认所有任务要求都被满足。

> 这里的设计取向值得注意
> 
> 三个角色的权限划分是精心设计的。执行 agent 独占记忆的写入权，验证 agent 独占「判真假」的权力，课程 agent 独占「决定探索方向」的权力。这种 **职责分离** 是为了避免一个 agent 既当运动员又当裁判——验证 agent 与执行 agent 的私有推理和记忆相互隔离，正是为了减少评估时的相关性错误。

## 4\. 实验结果

### 4.1 设置

RSIAgent 在两个需要 agent 在交互式软件环境里完成任务的基准上评测： **OSWorld 2.0** （0808 离线版，汇总 82 个离线任务）和 **Agents' Last Exam (ALE)** Near-term（覆盖全部 67 个 Near-term 任务）。

报两个指标： **partial score** （平均任务得分）和 **binary accuracy** （拿到满分的任务占比），都是百分比。

底座模型配置是： **GLM-5.3 作默认执行 agent** ， **Kimi-K3 同时作验证 agent 和课程 agent** （在独立上下文里）。两阶段探索都把目标查询作为课程 agent 的参考。

基线数据大多直接取自各模型官方技术报告或榜单。

### 4.2 主结果：开源模型反超闭源前沿

这张对比表按开源、闭源分组列出，加粗是每列最高分，「—」表示该榜或官方报告没有给出。

**先看自身增益。** 递归自我改进带来的提升在两个基准上都成立：

| 基准 | partial score | binary accuracy |
| --- | --- | --- |
| OSWorld 2.0 | 71.97 → **78.98** | 37.80 → **42.68** |
| Agents' Last Exam | 83.75 → **84.82** | 49.25 → **50.75** |

论文的解读是两阶段演化带来的增益 **同时体现在流程正确性和完整任务完成率上** 。对于没有完成 RSI 结果的任务，论文保留了它们的基线分数。

**再看跨模型对比。** 这是整篇最抓眼球的地方：

- • OSWorld 2.0 上 **78.98** ，比 GPT-6 Astra 的 72.60 高 **6.38 个百分点**
- • ALE 上 **84.82** ，比 GPT-6 Astra 的 82.26 高 **2.56 个百分点**
- • 两个基准上都高于 Claude Opus 5（70.19 / 79.54）

**底座只是开源的 GLM-5.3 加 Kimi-K3，全程没有更新任何模型参数。**

### 4.3 递归轮次：记忆积累是渐进，突破是离散

![图 3 · 三个 OSWorld 任务在 RSI 各步的 partial score 曲线](https://mmbiz.qpic.cn/mmbiz_png/yhDED7XRbyExnFOGAtgRatUYkxKmZ4KoicxNoyXB7ldkukWYfSKEGJ8CIVAju1NLSDN8RUv1sY2ibdWWADkheYsMstQWibozVbMSmOIY1B3kk0/640?from=appmsg#imgIndex=3)

图 3 · 三个 OSWorld 任务在 RSI 各步的 partial score 曲线

三条曲线分别是 T044（视频编辑）、T049（演示修复）、T065（铁路订票），横轴第 0 步是 RSIAgent (w/o RSI) 的空记忆基线。曲线形状很说明问题：

- • **T044** 在第 2 步就从 40% 冲到 100%
- • **T049** 在第 3 步之前一直卡在 40%，第 4 步跳到 80%
- • **T065** 最戏剧化，第 6 步之前一直是 **0** ，第 7 步直接跳到 **100%**

到第 8 步，三个任务分别达到 **100%、80% 和 100%** 。

论文的解释是：BRS 逐步把多样流程和环境知识累积进记忆，DRS 则精炼任务相关的细节。当这些知识 **覆盖了目标任务的关键要求** ，解决掉最后一个瓶颈就会产生 **离散的分数跃升** 。这种单任务评测比渐进式的记忆累积更容易暴露突破点。

### 4.4 消融：两阶段缺一不可

![图 4 · 四个 OSWorld 任务上 BRS / DRS 阶段对比](https://mmbiz.qpic.cn/sz_mmbiz_png/yhDED7XRbyG8IWXoLWCjticH91Zf2JSmcXkdTCqzptGIM7ylzRnJmoLxjjzHDpZJKKPNZ4Brfuia2BUssia2mEZiaPJsSlrTfGW2CR7RicU4Y9Ns/640?from=appmsg#imgIndex=4)

图 4 · 四个 OSWorld 任务上 BRS / DRS 阶段对比

四个任务分别是 T080（电子表格修复）、T085（音频编辑）、T089（网页演示修复）、T106（3D Slicer 肝脏分割），平均分对比：

| 变体 | 平均 partial score |
| --- | --- |
| **Full RSI** | **74.54%** |
| w/o DRS（仅广度探索） | 65.52% |
| w/o BRS（仅深度探索） | 56.50% |

两个观察：

1. 1\. **广度探索在每个任务上都优于基线** ，而 **深度探索在 T085 和 T089 上反而低于基线**
2. 2\. 两阶段结合在四个任务上都是最高分

> 这组消融真正说明的东西
> 
> 单独做广度探索是稳的——它在每个任务上都比基线好。单独做深度探索则 **有风险** ，在两个任务上比什么都不做还差。原因在于 DRS 是在 **空记忆** 起步的（w/o BRS 的设定），没有广度探索铺好的环境认知，深度探索很容易一头撞进未知的坑里。这解释了为什么两阶段的顺序不能颠倒： **先铺开认知面，再在认知面上攻坚** 。

### 4.5 跨域验证：游戏开发环境

论文进一步检验 RSIAgent 能否泛化到 **自主游戏开发** ——这需要 agent 反复试玩、诊断、修改可执行游戏，是比标准计算机操作任务更苛刻的交互场景。

从 GameCraft-Bench 随机采样 **40 个任务** ，与 Play2Code 对比——后者是一个基于迭代试玩和代码修改的持续游戏改进基线。

| 基线生成器 | Baseline | \+ Play2Code | \+ RSIAgent (w/o RSI) | \+ RSIAgent |
| --- | --- | --- | --- | --- |

1. 1\. **RSIAgent 在所有基线生成器上都大幅提升游戏质量**
2. 2\. **Play2Code 从弱生成器出发有增益，但基线游戏越强收益越小，甚至会拉低已经高质量的游戏** ——注意 Codex + GPT-5.5 那一行，Play2Code 的 51.05 **低于** 原始基线 52.77
3. 3\. **叠加 RSI 经验能进一步提升质量** ，累积经验为诊断和编辑不同类型的游戏提供了可复用知识

> 一个容易被忽略的对比
> 
> 最能说明问题的不是 RSIAgent 赢了多少，而是 **Play2Code 在最强生成器那一行是负收益** （52.77 → 51.05）。这暗示了一个区别： **在已有高质量产出上做「再编辑」是有风险的** ，而 RSIAgent 的路径是先探索、建立因果认知，再执行——这个顺序让它在强基线上依然能继续往上走。

## 5\. 失败模式：三个机制互相放大

论文的失败分析识别出三个限制递归自我改进的机制，而且它们 **会互相作用** ——让最初不确定或可能错误的操作在练习中持续存在，进而影响后续 agent 行为。

案例审计统计出的子类型分布很不均匀：探索定位不足 4 例中 3 例是目标技能错配、1 例是未经检验的假设；验证不完整 6 例中 3 例是保真度缺口、2 例接地缺口、1 例覆盖缺口；记忆固化不可靠 3 例中 2 例是规则范围丢失、1 例是不确定性未被强制。

### 5.1 探索定位不足

**当额外练习没有挑战到真正导致问题的那些决策时，目标特定的弱点就可能没被解决。**

在被审查的轨迹里，课程 agent 生成了涉及文档处理、冲突信息、提交持久化的练习，而「获取不可用的用户信息」这件事 **从未被测试** 。于是那条有问题的「缺失信息」处理规则就一直留在记忆里。

论文的结论是： **选择能挑战不确定知识、针对未解决目标要求的经验，比单纯扩大练习任务的多样性更重要。**

### 5.2 验证不完整

**局部验证可以在没有确认所有任务要求都被满足的情况下，批准一次执行。**

在被审查的案例里，验证 agent 在官方评分标准下面对不支持的字段值或产物差异，仍然返回了 PASS。 **检查某个预期产出是否生成了，并不能确认底层的理解或要求清单是完整的。**

这个缺口会同时影响最终执行和后续学习—— **一个被接受的错误，可能成为未来记忆更新和探索决策的基础。**

### 5.3 记忆固化不可靠

**一个验证不足的决策，会变成一条可复用的规则，对后续执行产生负面影响。**

在被审查的表单填写运行里，执行 agent 保留了两条有问题的规则：把「缺失数据标记」当作有效答案，以及把「不可用信息」解释为否定答案。后续尝试直接复用了这些规则， **却没有去获取那些缺失的事实** 。

论文指出这说明： **有用的记忆必须保留一条经验的条件和不确定性** ，而不是只保留结论。

> 我的质疑：三个机制的因果方向
> 
> 这三个机制在论文里是并列陈述的，但看描述更像一条 **因果链** ：验证不完整 → 错误经验被固化进记忆 → 记忆里有问题的规则让执行 agent 反复踩坑 → 探索 agent 看不到这些失败（因为执行「成功」了）→ 课程 agent 也就无从针对它出题。如果是这样，那真正需要修的是 **验证环节** ，而探索策略的调整只是补救。这篇论文没有做这个拆解实验，但它对失败模式的归因排序是并列的，我觉得值得读者自己判断哪个是根因。

## 6\. 总结

RSIAgent 把「适应新环境」从数据问题改写成了探索与记忆管理问题：不更新任何参数，靠课程、执行、验证三个 agent 组成的递归闭环自主摸路，先广后深两阶段探索把陌生环境一点点变成可复用的记忆。底座只是开源的 GLM-5.3 加 Kimi-K3，却在 OSWorld 2.0 和 ALE 上反超了 GPT-6 Astra；消融也显示两阶段缺一不可，单独做深度探索甚至低于基线。代价是额外的测试时探索成本，以及验证 agent 一旦出错、错误就会被忠实固化并一路传播下去。

> Takeaway
> 
> 这篇论文的主要亮点之一是 **职责分离的设计** 。执行 agent 独占写入、验证 agent 独占判定且对执行方隔离、课程 agent 独占方向决策——三个权力互相制衡，记忆才能既积累又不腐化。反过来看，失败模式那条链也正是这个设计的代价：一旦验证环节出错，错误就会被忠实地固化下来。 **这个框架的天花板不在于探索策略，而在于验证的可靠性。**
